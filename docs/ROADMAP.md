# 로드맵

Phase 1(매물 트래커 코어)은 끝났습니다.

---

## 이 앱이 풀려는 문제

처음에는 "고른 매물을 기록한다"로 시작했지만, 실제 병목은 그 앞에 있었습니다.

> **손품** — 호갱노노·네이버부동산에서 조건에 맞는 매물을 찾을 때,
> 매번 필터를 다시 걸고, 결과를 하나씩 지도로 열어 지하철·마트·학교가 가까운지 눈으로 확인하는 반복 작업.

여기 드는 시간을 쪼개면 세 덩어리입니다.

| | 시간이 드는 일 | 자동화 가능? |
|---|---|---|
| ① | 매번 지역·평수·가격·연식 **필터를 다시 설정** | 가능 — 저장된 검색 바로가기 (2-1) |
| ② | 후보를 하나씩 **지도 켜서 인프라 확인** | **가능 — 공식 API로 자동 조회 (2-2)** |
| ③ | 괜찮은 것만 어딘가에 **기록** | Phase 1 에서 이미 해결 |

**②가 가장 크고, 가장 확실하게 자동화됩니다.** 10개 후보를 등록하면 10개 모두
"지하철 도보 8분 · 초등학교 5분 · 반경 500m 마트 2곳"이 자동으로 채워집니다.

### 자동화되지 않는 것

**"조건을 넣으면 매물을 찾아준다"는 만들 수 없습니다.** 실거래가는 정부가 법으로 공개하지만,
호가(현재 나와 있는 매물)는 공인중개사가 네이버·직방에 올린 사적 정보라 **공개된 원천이 없습니다.**
긁어오는 것 외에 방법이 없고, 그건 하지 않기로 했습니다(맨 아래 참고).

그래서 워크플로우는 이렇게 바뀝니다.

```
[지금]  매번 필터 재설정 → 결과 하나씩 지도 켜서 인프라 확인 → 괜찮은 것만 수기로 기록
[목표]  저장된 조건 클릭 → 후보만 빠르게 등록 → 인프라·실거래가는 자동으로 채워짐
```

검색 자체가 사라지는 게 아니라, **검색과 검색 사이의 반복 작업**이 없어집니다.

# Phase 2 — 손품 줄이기

## 2-1. 저장된 검색 바로가기 + 빠른 등록 ← 가장 싸고 효과가 큼

### 저장된 검색

조건 조합(예: "분당 30평대 · 10억 이하 · 2005년 이후")마다 **이름 + 메모 + 바로가기 URL**을 저장하고,
목록 상단이나 대시보드에서 한 번에 열 수 있게 합니다.

```prisma
model SavedSearch {
  id String @id @default(cuid())
  name String            // "분당 30평대 10억 이하"
  note String?           // 조건을 사람이 읽을 수 있게 적어둔 것
  url  String            // 네이버부동산·호갱노노에서 복사해 온 링크
  site String?           // 네이버 | 호갱노노 | 아실 …
  sortOrder Int @default(0)
  lastOpenedAt DateTime?
}
```

> **URL 을 앱이 조립하지 않고, 사용자가 붙여넣습니다.**
>
> `new.land.naver.com` 은 SPA 라 필터가 URL 쿼리스트링이 아니라 내부 API 호출로 처리될 가능성이 높습니다.
> 파라미터를 역공학해 조립하면 사이트가 바뀔 때마다 깨지고, 애초에 동작 보장이 안 됩니다.
>
> 대신 **사이트에서 필터를 한 번 걸고 주소창을 복사해 붙여넣는** 방식을 씁니다.
> 역공학이 필요 없고, 깨지면 다시 붙여넣으면 그만이며, 호갱노노·아실·직방 어디든 똑같이 동작합니다.
> 호갱노노에는 자체 "필터 저장" 기능도 있으니 그 결과 URL 을 그대로 담으면 됩니다.
>
> *구현 시 확인할 것*: 네이버부동산 URL 이 실제로 필터 상태를 유지한 채 복원되는지.
> 안 되는 사이트는 `note` 에 조건을 적어두고 링크는 지역 화면까지만 여는 식으로 낮춰 잡습니다.

### 클립보드 붙여넣기로 빠른 등록

매물 페이지에서 **본문을 긁어 복사한 뒤 붙여넣으면** 단지명·면적·층·가격·준공년도를 파싱해 폼을 채웁니다.
크롤링이 아니라 **이미 보고 있는 화면의 텍스트를 옮기는 것**이라 차단 대상도 아니고 약관 문제도 없습니다.

- `lib/paste-parser.ts` 에 격리. 정규식으로 `84.96㎡`, `12/25층`, `5억 8,000`, `2009년 준공` 같은 패턴을 뽑습니다
- 파싱은 **보조**일 뿐입니다. 못 읽은 필드는 비워두고 사용자가 채웁니다 — 틀린 값을 채워 넣는 것보다 낫습니다
- 기존 `parseManwon()`(`lib/money.ts`)을 그대로 재사용합니다

## 2-2. 인프라 자동 조회 ← 손품의 핵심

매물에 좌표가 있으면, **반경 안의 생활 인프라를 공식 API 로 자동 조회**해 채웁니다.
사람이 지도를 켜서 하나씩 확인하던 일이 없어집니다.

```prisma
model ListingPlace {
  id String @id @default(cuid())
  listingId String
  listing Listing @relation(fields: [listingId], references: [id], onDelete: Cascade)

  category String   // 지하철역 | 대형마트 | 초등학교 | 공원 | 병원 …
  name     String   // "수내역"
  distanceM Int     // 직선거리(m)
  walkMinutes Int?  // 도보 분 — 길찾기 API 를 붙이면 채운다
  lat Float   lng Float
  fetchedAt DateTime @default(now())

  @@index([listingId, category])
}
```

### 데이터 출처 (전부 공식 · 합법)

| 항목 | 출처 |
|---|---|
| 지하철역 · 마트 · 편의점 · 병원 · 공원 | **카카오 로컬 API** 카테고리·키워드 검색 |
| 주소 → 좌표 (지오코딩) | 카카오 로컬 API |
| 초등학교 위치·학생수·기본정보 | **[학교알리미](https://www.schoolinfo.go.kr/)** / [나이스 교육정보 개방포털](https://open.neis.go.kr/) |
| 상권 규모 (업종별 상가 밀집도) | **[소상공인시장진흥공단 상가정보 API](https://www.data.go.kr/data/15012005/openapi.do)** — 국세청·카드사 기반 |
| 경사도 | **[브이월드](https://www.vworld.kr/)** 수치표고모델(DEM) — 3차원 분석 기능 제공 |

> 카테고리 코드(지하철역·대형마트 등)는 **구현 시 카카오 개발자 문서로 확인**하고
> `lib/places.ts` 한 곳에 격리합니다. "공원" 처럼 표준 카테고리가 없는 항목은 키워드 검색으로 대체합니다.

### 설계 규칙

- **조회는 명시적 버튼 + 결과 캐시.** 화면 열 때마다 호출하지 않습니다. `fetchedAt` 을 함께 보여줍니다
- **반경은 설정 가능**(기본 500m). 도보 분은 직선거리 기준 근사치로 시작하고, 정확한 값이 필요해지면 길찾기 API 를 붙입니다
- 조회 결과는 **목록 필터로 이어집니다** — "지하철 도보 10분 이내"로 거를 수 있게
- **키가 없어도 앱 전체는 정상 동작**해야 합니다. 해당 영역만 안내 문구로 대체

### 왜 이게 크롤링보다 나은가

호갱노노가 보여주는 학군·상권·경사도는 **원천이 전부 공개 데이터**입니다.
그 회사가 만든 것은 원천이 아니라 가공·시각화입니다. 그래서 같은 원천으로 직접 계산하면
긁어올 이유가 없고, 차단당하지도 않고, 사이트 개편에 깨지지도 않습니다.

## 2-3. 국토부 실거래가 연동

```
GET https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade
    ?serviceKey={KEY}&LAWD_CD={법정동 앞 5자리}&DEAL_YMD={YYYYMM}&pageNo=1&numOfRows=1000
전월세: .../1613000/RTMSDataSvcAptRent/getRTMSDataSvcAptRent
```

키는 [공공데이터포털](https://www.data.go.kr/data/15126469/openapi.do)에서 발급받아 `.env` 의 `MOLIT_API_KEY` 에 넣습니다.
2006년 이후 데이터. 응답 스키마는 구현 시점에 포털 문서로 다시 확인하고,
파싱은 `lib/molit.ts` **한 곳에 격리**하세요.

> **⚠ 진짜 난점은 API 호출이 아니라 단지 매칭입니다.**
>
> API 는 법정동코드+년월로 **그 동네 전체 거래**를 줍니다. 내 매물과 이어붙이려면 단지명을 맞춰야 하는데,
> 표기가 흔들립니다 — `래미안퍼스티지` / `반포래미안퍼스티지` / `래미안 퍼스티지`.
> 전용면적도 `84.96` vs `84.9562` 로 어긋납니다.
>
> 1. 공백·특수문자를 제거해 정규화한 뒤 부분일치로 후보를 뽑고
> 2. 후보가 여럿이면 **사용자가 한 번 고른 매핑을 저장**(`ListingComplexMapping`)
> 3. 이후로는 자동. 면적은 **±0.5㎡ 허용 범위**로 매칭
>
> **[국토부 공동주택 단지 목록 API](https://www.data.go.kr/data/15057332/openapi.do)** 를 기준 테이블로 두면
> 이 문제가 상당 부분 풀립니다. 단지명 자동완성 + 주소·세대수·준공년도 자동 입력까지 덤으로 따라오므로,
> **실거래가 연동보다 먼저 붙이는 편이 나을 수 있습니다.**

**캐시 전략**: "실거래가 갱신" 버튼 + 마지막 수집 시각 표시, 조회는 항상 `Transaction` 캐시 우선.
`(lawdCd, dealYmd)` 유니크로 중복 수집을 막습니다.

**활용**: 호가 괴리율 `(내 호가 − 최근 실거래 중앙값) / 중앙값 × 100` ·
아실식 시세 겹쳐보기 차트 · 전세가율 자동 계산(2-6 으로 이어짐)

> 실거래가는 계약 후 **30일 이내 신고**라 최근 1~2개월치는 아직 채워지는 중입니다.
> 호가는 지금 이 순간의 협상 시작점이고, 실거래가는 지나간 사실입니다. 둘은 서로를 대체하지 않습니다.

## 2-4. 지도 뷰

2-2 에서 좌표와 인프라가 이미 채워져 있으므로, 여기서는 **보여주기**만 하면 됩니다.
카카오맵 JS SDK(무료 키) — 가격 라벨 마커, 상태별 색상, 인프라·통근 목적지 핀, 반경 원.

*순서상 2-2 뒤인 이유*: 지오코딩이 먼저 돌아야 지도에 찍을 게 생깁니다.
키가 없으면 지도 탭만 숨기고 나머지는 정상 동작.

| 3D 일조량 시뮬레이션 | 브이월드에 3D 건물·DEM 이 있어 이론상 가능하지만, 태양궤도·그림자 연산은 개인 트래커 규모를 넘습니다 |
| AI 미래 시세 예측, 매수심리, 입주물량 | 리치고·아실의 영역. 데이터 정제 노하우까지 재현하는 건 다른 이야기입니다 |
| 취득세·양도세 정밀 계산 | 부동산계산기.com 이 이미 정확. 세법 개정 추적 부담만 짐 |

### 크롤링에 대한 선

**해도 되는 것과 안 하는 것의 기준은 "누가 보느냐"가 아니라 "얼마나 자동화·반복적이냐"입니다.**

| | |
|---|---|
| ✅ 화면을 보다가 **손으로 복사해 붙여넣기** | 크롤링이 아니라 그냥 이용입니다 (2-1) |
| ✅ 공식 API 로 **좌표를 물어보기** | 그 사이트를 긁는 게 아닙니다 (2-2) |
| ❌ **주기적·자동으로 매물을 수집** | 개인용이어도 "체계적 수집"에 해당하고, 기술적으로도 계속 깨집니다 |

판례에서 침해 기준은 **"반복적·체계적 복제가 상당 부분의 복제와 같은 결과를 낼 때"**입니다.
[다윈중개는 네이버 부동산 매물 크롤링으로 2심까지 패소](https://www.etnews.com/20241007000224)해 손해배상과 데이터 삭제 명령을 받았습니다.
네이버 이용약관 제10조는 목적을 따지지 않고 자동화 수단 접근 자체를 금지합니다.

개인이 어쩌다 한 번 스크립트를 돌리는 것과 서비스가 대량 수집하는 것은 정도가 다르지만,
**앱에 자동 수집 기능으로 내장하는 것**은 그 선을 넘습니다. 게다가 IP 차단·캡차·구조 변경으로
유지비가 계속 드는데 언제 막힐지 모르는 기능이 됩니다.

나머지는 **딥링크로 위임**했습니다 (`lib/links.ts`). 서비스가 URL 형식을 바꾸면 그 파일만 고치면 됩니다.

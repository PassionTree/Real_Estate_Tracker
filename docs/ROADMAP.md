## Phase 2 — 엑셀로는 안 되는 것들

### 2-1. 국토부 실거래가 연동 ← 다음으로 할 만한 것

```
GET https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade
    ?serviceKey={KEY}&LAWD_CD={법정동 앞 5자리}&DEAL_YMD={YYYYMM}&pageNo=1&numOfRows=1000
전월세: .../1613000/RTMSDataSvcAptRent/getRTMSDataSvcAptRent
```

키는 [공공데이터포털](https://www.data.go.kr/data/15126469/openapi.do)에서 발급받아 `.env` 의 `MOLIT_API_KEY` 에 넣습니다.
2006년 이후 데이터. 응답 스키마는 구현 시점에 포털 문서로 다시 확인하고,
파싱은 `lib/molit.ts` **한 곳에 격리**하세요. 포맷이 바뀌면 거기만 고치면 됩니다.

> **⚠ 진짜 난점은 API 호출이 아니라 단지 매칭입니다.**
>
> API 는 법정동코드+년월로 **그 동네 전체 거래**를 줍니다. 내 매물과 이어붙이려면 단지명을 맞춰야 하는데,
> 표기가 흔들립니다 — `래미안퍼스티지` / `반포래미안퍼스티지` / `래미안 퍼스티지`.
> 전용면적도 `84.96` vs `84.9562` 로 어긋납니다.
>
> 설계 없이 시작하면 구현 중에 반드시 막힙니다. 해결:
> 1. 공백·특수문자를 제거해 정규화한 뒤 부분일치로 후보를 뽑고
> 2. 후보가 여럿이면 **사용자가 한 번 고른 매핑을 저장**(`ListingComplexMapping`)
> 3. 이후로는 자동. 면적은 **±0.5㎡ 허용 범위**로 매칭

**캐시 전략**: 화면 열 때마다 호출하지 않습니다.
"실거래가 갱신" 버튼 + 마지막 수집 시각 표시, 조회는 항상 `Transaction` 캐시 우선.
`(lawdCd, dealYmd)` 를 유니크로 걸어 중복 수집을 막습니다.

**활용**:
- 호가 괴리율 — `(내 호가 − 최근 실거래 중앙값) / 중앙값 × 100`
- 아실식 시세 겹쳐보기 차트 — 선택한 매물들의 실거래가 추이를 한 차트에
- 전세가율 자동 계산 — 2-4 의 위험 경고로 이어집니다

**키가 없어도 앱 전체는 정상 동작해야 합니다.** 해당 영역만 안내 문구로 대체하세요.

### 2-2. 지도 뷰

카카오맵 JS SDK(무료 키) + 카카오 로컬 API 지오코딩.
가격 라벨 마커, 상태별 색상, 통근 목적지 핀.
키가 없으면 지도 탭만 숨기고 나머지는 정상 동작. 지오코딩 실패 시 좌표 수동 입력 폴백.

*Phase 1에서 뺀 이유*: 개별 위치 확인은 네이버지도 딥링크로 되고,
전체 조망의 가치는 매물이 10건 넘게 쌓인 뒤에 생깁니다.

### 2-3. 임장 기록 + 사진

`Visit`(날짜·동행자·체크리스트·메모) + `VisitPhoto` 업로드.
체크리스트는 `data/checklists/visit.json` 으로 관리 —
채광·소음·수압·곰팡이·결로·주차·엘리베이터·경사도·주변 혐오시설·관리상태.

*Phase 1에서 뺀 이유*: multipart 처리, 폰 사진 리사이즈(5MB+), 정적 서빙, 백업 대상 추가 —
보이는 것보다 비쌉니다. **다만 3개월 뒤 사진 없이는 아무것도 기억 못 하므로 Phase 2 안에서는 우선순위가 높습니다.**

### 2-4. 권리관계 · 전세사기 체크

[정책브리핑 체크리스트](https://www.korea.kr/multi/visualNewsView.do?newsId=148905628) 기반:
등기부 을구 근저당·가압류 · 소유자 실명 일치 · 임대인 세금체납 · 선순위 보증금 ·
확정일자·전입세대 열람 · 표준계약서 · 보증보험 가입가능 여부.

**등기부등본은 계약일과 잔금일 2회 열람**이 권고이므로 각각 체크하게 합니다 (700원, [인터넷등기소](https://www.iros.go.kr/)).
전세가율 임계값(주의 70% / 위험 80%)은 **출처·기준일과 함께 정책 JSON** 에 두고 화면에 근거를 같이 띄웁니다.
거래유형에 따라 항목을 바꿉니다 — 매매는 근저당·가압류 위주.

*Phase 1에서 뺀 이유*: 이건 **계약 직전**에 쓰는 기능이고, 지금은 매물을 모으는 단계입니다.

> 법률 자문이 아니라 체크리스트입니다. 최종 확인은 공인중개사·법무사 몫으로 남겨야 합니다.

### 2-5. 통근 시간 다중 목적지

`CommuteTarget`(직장A·직장B·친정) × 매물. Phase 1 의 단일 `commuteMinutes` 를 확장.
입력은 수동 + 카카오맵 길찾기 딥링크.
**"실제 출근 시간대에 재보세요"** 안내를 붙입니다 — 거리가 아니라 도어투도어 시간이 변수입니다.

## Phase 3 — 링크 허브를 자체 기능으로

- **`/finance`** — LTV/DTI/DSR 한도, 원리금균등·원금균등 상환 스케줄, 자금 시나리오 비교 차트
- **`/policy`** — 규제지역, LTV·DSR 규제, 취득세·보유세·양도세, 청약 제도 (전부 `asOf` + 출처)
- **`/market`** — 실거래가 캐시 기반 지역별 추이 (입주물량·매수심리는 계속 아실·부동산지인에 위임)
- 저장된 검색 + 신규 실거래 알림 (크롤링 없이 실거래가 기반으로만)
